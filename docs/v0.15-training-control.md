# v0.15 — Training control

v0.15 adds two controls to the high-level loop: global gradient clipping per batch and stepwise learning-rate decay per completed epoch.

## Gradient norm clipping

`gradientNorm parameters` returns the global L2 norm across every gradient component. `clipGradNorm.max: limit parameters` returns the original norm and rescales every gradient by the same factor when it exceeds `limit`.

```arturo
backward model\loss
originalNorm: clipGradNorm.max: 1.0 (parameters model)
step optimizer
```

The high-level equivalent is `train.clip: 1.0`. Clipping happens after backward and before the optimizer step.

## Epoch scheduling

`stepLr` multiplies an optimizer's rate after every configured number of completed epochs.

```arturo
scheduler: stepLr.every: 5.factor: 0.5 optimizer
history: train.epochs: 20.scheduler: scheduler model optimizer iterator
```

Each epoch history record includes `learningRate`, the rate used for that epoch. `schedulerStep` can also be called directly. `schedulerState` and `loadSchedulerState` expose and restore the scheduler's configuration, completed-epoch count, and optimizer rate.

## Resumable state

The existing session checkpoint remains backward compatible when called without a scheduler. Supplying `.scheduler:` writes the v0.15 extended payload:

```arturo
saveSessionCheckpoint.scheduler: scheduler model optimizer iterator path
loadSessionCheckpoint.scheduler: scheduler model optimizer iterator path
```

Loading validates model, optimizer, batcher, and scheduler state before mutating any of them. The supplied scheduler must own the same optimizer passed to the checkpoint function.
