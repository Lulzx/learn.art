# v0.31 mutable view assignment

v0.31 adds `assignTensor target replacement` for owned tensors and `tensorSlice` views. A scalar fills the target; a tensor replacement must have the same shape and dtype. Assignment returns the target and preserves its device and dtype.

View assignment always snapshots replacement values before changing the root tensor. Overlapping operations such as shifting one slice into another therefore have deterministic copy semantics instead of depending on traversal order. Every root carries a mutation version. Cached host projections and backend-native slice projections record that version and are rebuilt lazily after any alias writes, so sibling views observe the updated root rather than stale caches.

Device assignment builds a complete replacement allocation first, atomically swaps the shared ownership record to the new handle, and only then releases the prior allocation. Existing view references remain valid because they share the ownership record, while readers never observe a partially written buffer. This portable implementation crosses the host boundary; backend-native scatter updates and zero-copy reshape/transpose views remain future work.
