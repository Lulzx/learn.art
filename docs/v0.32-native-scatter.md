# v0.32 native scatter assignment and shape views

v0.32 extends the mutable view story in two directions: view assignment can now run as a backend-native scatter, and `reshape`/`transpose` produce zero-copy lazy views instead of eager owned copies.

## Native scatter assignment

`assignTensor` on a view used to download the full root, apply indices on the host, and upload a complete replacement. A backend with a `scatter` capability can instead produce the replacement allocation entirely on the device: the Metal backend implements `am_scatter`, which builds an MPSGraph that flattens the root, scatters the replacement values at the view's root positions with `MPSGraphScatterModeSet`, and restores the original shape. Only the indices and values cross the host boundary.

The shared ownership record is updated atomically exactly as before: the backend returns a new handle, the record swaps to it, the prior allocation is released, and every alias observes the new storage through the versioned caches. Sibling views keep their lazily rebuilt projections; when the root's host mirror is already materialized it is updated in place so later host reads need no download, and when it is not it is invalidated so the next materialization re-reads the swapped handle.

Assignment still validates shape and dtype, snapshots replacement values first (so overlapping writes are deterministic), and falls back to the portable host path whenever the backend descriptor has no `scatter` capability.

## Zero-copy reshape and transpose views

`reshape` and `transpose` now return lazy `tensorSlice`-style views instead of eager owned tensors. View projections are tagged operations (`slice`, `reshape`, `transpose`) composed from the root, and both the host projection and the backend-native projection dispatch on the tag. Reshape preserves flat order on the host and shares the device buffer through `am_reshape`; transpose permutes on either side. Chained shape views stay lazy until host data or a compiled feed is actually needed, so a device tensor can be reshaped, transposed, and fed to an MPS program without a single download.

Autograd and the CPU schedule executor materialize node values eagerly, so differentiation and compiled graphs keep their owned-tensor invariants. Data-prep helpers in `regression` materialize their reshapes explicitly. Host reads use `tensorData` (or any tensor operator), which lazily materializes the projection and caches it against the mutation version.

Read the previous milestone notes for the shared storage and versioned cache semantics that these projections build on.
