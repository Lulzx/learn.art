# v0.30 native views and shared storage

v0.30 lets an optional backend implement `slice` to realize a lazy `tensorSlice` projection without first downloading its source. Contiguous slices map directly to the Metal slice primitive; positive strides use a device-side gather. Nested views retain an ordered projection from the root allocation, so compiled MPS programs can consume them directly while their host cache remains empty.

Device allocations now have a small mutable ownership record with an explicit reference count. Creating a view retains its root allocation. Releasing the source only drops the source reference, so an unmaterialized view remains valid; the backend handle is released exactly once when the last tensor or view reference is released. A backend-native projection has its own ownership record and is also released by `releaseTensor view`.

CPU-only portability is unchanged. The core probes the backend descriptor for optional native slicing and otherwise evaluates the same projection against host data. Views remain read-only in v0.30; mutable aliasing and overlap-safe copy-on-write assignment are the next boundary.
