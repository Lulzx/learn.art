# v0.28 lazy host materialization

v0.28 removes the implicit GPU-to-host transfer from compiled MPS results. `executeMps` now returns an MPS tensor whose storage is immediately reusable as another compiled feed while its host `data` block remains empty. `executeMpsTraining` does the same for its one-element loss result; model parameters and optimizer slots continue to remain resident in the training artifact.

`hostMaterialized?` reports whether a tensor currently has a complete host mirror. `materializeTensor` downloads once, validates the backend result, caches an owned floating-point block on the tensor, and returns that tensor. `tensorData` crosses the same boundary but returns an owned copy. `tensorBuffer`, eager tensor operations, and transfers that require host values materialize automatically.

Compiled training loss is explicit:

```arturo
result: executeMpsTraining.with: feed artifact
loss: mpsTrainingLoss result
releaseTensor result
```

The caller owns each compiled inference or training result and should call `releaseTensor` when its device storage is no longer needed. Repeated materialization uses the cached host block and does not download again.

The fixed MPS MLP/MNIST workflow retains its numeric `mpsMlpStep` result so the established one-epoch MNIST path remains an end-to-end regression test. The default `src/learn.art` import still registers only CPU support: all lazy behavior is expressed through the backend registry, with no Metal symbols in the portable tensor core.
