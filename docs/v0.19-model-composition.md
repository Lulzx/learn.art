# v0.19 — Model composition

v0.19 introduces reusable dense-layer objects, nested parameter discovery, stable parameter groups, selective freezing, and resumable trainability state.

## Reusable layers

```arturo
encoder: denseLayer.name: "encoder" 4 8
head: denseLayer.name: "head" 8 3

model: graph [
    x: inputShape [1 4]
    hiddenLinear: applyLayer encoder x
    hidden: relu hiddenLinear
    logits: applyLayer head hidden
    loss: crossEntropy logits y
]
```

As of v0.20, `denseLayer` initializes weights with the local seeded Xavier strategy and biases with zeros; add `.zeros` for deterministic zero weights or pass `.initializer:` explicitly. `layerParameters layer` returns its weight and bias.

`applyLayer` creates one `dense` graph operation with input, weight, and bias parents. Its eager and scheduled CPU implementations compute matrix multiplication plus broadcasted bias, and backward produces input, weight, and bias gradients.

## Nested discovery and names

Graph construction walks each named value's topology. Reachable parameter values are deduplicated by identity, including a layer reused more than once. Parameters not already labeled in the graph are promoted to named graph nodes using the layer-qualified names `<layer>_weight` and `<layer>_bias`.

Those names are used consistently by `graphData`, `stateDict`, strict checkpoint restoration, and optimizer parameter order. Creating two nested layers with the same name in one graph is rejected as a name collision.

## Groups and freezing

`parameterGroups model` returns a dictionary of layer-name to parameter block. `parameters.group: "encoder" model` selects one group, while `trainableParameters model` returns only values whose gradients are enabled.

```arturo
freezeGroup model "encoder"
train.epochs: 10 model optimizer iterator
unfreezeGroup model "encoder"
```

`freezeParameters` and `unfreezeParameters` also accept a layer, graph, explicit parameter block, or individual parameter. Frozen parameters remain in model and optimizer state but do not accumulate gradients or receive optimizer updates.

`trainabilityState` and `loadTrainabilityState` validate and restore every named parameter flag. Session checkpoints now use header `10019` and include trainability automatically, while loading remains compatible with headers `10013`, `10015`, and `10018`.
