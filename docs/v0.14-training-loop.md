# v0.14 — Resumable training loop

v0.14 turns graphs, optimizers, and deterministic batchers into one high-level training operation without hiding their state.

```arturo
iterator: batcher.size: 16.seed: 42 xTrain yTrain
validation: #[features: xValid targets: yValid]
history: train.epochs: 20.validation: validation model optimizer iterator
```

`train` performs zero-gradient, forward, backward, and optimizer steps for every remaining batch in each requested epoch. Its result is an ordinary dictionary with format `learn.training-history`, version `0.14`, per-epoch weighted mean losses, validation losses, and batch accounting.

## Named feeds and loss

The defaults are graph inputs `x` and `y` and graph output `loss`. Other graph dialects can declare the mapping explicitly:

```arturo
history: train.epochs: 10
              .inputs: ['features 'labels]
              .loss: 'objective
              model optimizer iterator
```

## Validation and stopping

Validation data uses the same named input mapping. Validation runs forward passes only, so optimizer state and step counts are unchanged.

A callback is an Arturo function named by a literal. It receives the completed epoch record and returns a logical value; `false` stops training after that epoch.

```arturo
keepTraining: function [record][record\validationLoss > 0.01]
history: train.epochs: 100
              .validation: validation
              .callback: 'keepTraining
              model optimizer iterator
```

If a restored batcher is partway through an epoch, the first history record covers only the remaining rows and sets `partial: true`. After any completed epoch, the batcher points at the beginning of the next deterministic permutation and can be saved with `saveSessionCheckpoint`.
