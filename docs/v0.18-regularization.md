# v0.18 — Explicit regularization

v0.18 adds seeded inverted dropout, explicit graph train/eval mode, differentiable parameter penalties, and resumable regularization state.

## Dropout and graph mode

```arturo
dropped: dropout.rate: 0.25.seed: 42 hidden
```

In training mode, retained values are multiplied by `1 / (1 - rate)`. Each dropout node owns an independent deterministic sequence identified by its seed and completed-forward counter. Backward multiplies by the mask saved by that node's most recent forward pass.

Graphs start in training mode. `trainMode model` enables dropout, `evalMode model` makes it an identity, and `trainingMode? model` inspects the current mode. The high-level `train` loop enforces training mode for optimization batches and evaluation mode for validation, restoring training mode afterward.

Graph forward execution now builds the union of each named value's topology and recomputes every shared or unnamed node once. This is important for stochastic nodes: one logical forward pass advances each dropout counter exactly once.

## Parameter penalties

`l1Penalty.rate: amount parameters` sums absolute parameter values; `l2Penalty.rate: amount parameters` sums squares. Both produce differentiable scalar values and accept only non-empty parameter blocks.

```arturo
model: graph [
    weight: parameter.random [4 1]
    prediction: matmul x weight
    residual: prediction - y
    dataLoss: mean square residual
    penalty: l2Penalty.rate: 0.001 @[weight]
    loss: dataLoss + penalty
]
```

The L1 derivative is `-1`, `0`, or `1`; L2 contributes `2 * parameter * rate`.

## Resuming exactly

`regularizationState model` returns graph mode plus each named dropout node's rate, seed, and pass counter. `loadRegularizationState` validates the entire topology and configuration before mutation.

`saveSessionCheckpoint` now writes header `10018` and includes regularization state automatically. `loadSessionCheckpoint` remains backward compatible with v0.13 and v0.15 session payloads. Scheduler-aware calls keep the same `.scheduler:` API.
