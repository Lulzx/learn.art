# v0.23 — Gradient explainability

v0.23 adds named input gradients, saliency, and integrated gradients without contaminating an active training session.

## Input gradients and saliency

```arturo
gradient: inputGradient
              .input: 'features
              .output: 'score
              model feed

importance: saliency.input: 'features.output: 'score model feed
```

The default input is the graph's first declared input and the default output is its last named value. A non-scalar output requires `.index:`; use an integer for a vector or a coordinate block for higher rank.

Attribution temporarily enables gradient flow across the selected output topology, switches dropout to evaluation behavior, and performs a fresh forward/backward pass. It snapshots and restores every reachable node's gradient and `requiresGradient` flag, then restores the graph's previous train/eval mode. The returned tensor is owned.

`saliency` is the elementwise absolute input gradient.

## Integrated gradients

```arturo
attribution: integratedGradients
                 .steps: 64
                 .baseline: baseline
                 .input: 'features
                 .output: 'score
                 model feed
```

The default baseline is a zero tensor matching the selected input. The implementation samples the straight-line path at `steps` right-endpoint intervals, averages named input gradients, and multiplies by `input - baseline`.

For a linear scalar output, attribution sums exactly to the output difference from baseline. Nonlinear models converge toward that completeness relation as the number of steps increases.

All other feed entries are retained at their supplied values along the path. Baseline shape and device must exactly match the explained input.
