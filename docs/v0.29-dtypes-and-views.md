# v0.29 dtypes and read-only views

v0.29 adds explicit `float32` and `float64` identity to every tensor. Use `tensor.dtype:`, `dtypeOf`, and `toDtype` to construct, inspect, and convert values. Binary arithmetic and matrix multiplication promote to `float64` if either operand is `float64`; otherwise they remain `float32`. Unary operations, reductions, reshapes, transposes, preprocessing, batching, and eager gradients preserve their source dtype.

CPU supports both dtypes. Arturo still represents host components as floating-point values, so `float32` is a storage and execution contract rather than a separate host scalar type. The MPS backend advertises only `float32`, matching its native buffers. `toDevice` preserves a dtype when the target supports it and otherwise uses the target's default. Tensor buffers retain version `0.9` and now round-trip either supported dtype.

`tensorSlice.axis:.start:.count:.step:` returns a `learnTensorView`. A view records a read-only strided projection and preserves the source shape relationship, dtype, and device without copying immediately. `tensorData`, `tensorBuffer`, or an eager operation materializes and caches an owned flat projection. Views may be sliced again, and eager arithmetic produces an ordinary owned tensor.

In v0.29 the source remains responsible for backend storage and must outlive an unmaterialized view. v0.30 supersedes that restriction with shared reference-counted storage and optional backend-native slicing.
