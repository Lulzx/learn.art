# v0.9 — Device-aware storage

v0.9 makes placement part of tensor identity while retaining the existing owned `data` API.

## Added

- `tensor.device:` for explicit construction on an available device.
- `availableDevices` and `deviceOf` for placement discovery.
- Differentiable, copying `toDevice` transfers.
- `tensorBuffer` and `tensorFromBuffer` using the versioned `learn.buffer` contract.
- Device metadata in graph data, transformation signatures, constant folding, and aliases.
- CPU schedule placement validation and eager/reference parity tests.

## Buffer contract

A v0.9 buffer contains `format`, `version`, `device`, `dtype`, `count`, and an owned flat `data` block. The only current device is `cpu` and the only dtype is `float64`. Unsupported placement, versions, dtypes, counts, and shapes fail before tensor construction.

## Boundary

This milestone establishes transfer and storage semantics; it does not claim a GPU implementation. A future backend can add a device without changing tensor shapes, gradients, or graph meaning.
